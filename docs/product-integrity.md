# Integridad de productos: T-12

Domain y Application limitan el nombre a 200 y la descripción a 1000 unidades UTF-16; el precio debe estar entre 0 y 9999999999999999.99 y tener como máximo dos decimales significativos. Los ceros finales adicionales se aceptan. Update valida todo antes de cambiar campos o versión.

SQL Server emplea `nvarchar(200)` y `nvarchar(1000)`, que cuentan unidades UTF-16. El motor puede descartar espacios finales excedentes en SQL directo; la aplicación rechaza el texto original antes de persistirlo. PostgreSQL cuenta unidades como `2 * char_length(valor) - char_length(regexp_replace(valor, U&'[\+010000-\+10FFFF]', '', 'g'))`: cada carácter suplementario eliminado suma una unidad extra. Los CHECK y el preflight aplican la misma expresión a ambos campos. El límite superior de precio también rechaza `NaN` de PostgreSQL. Precio y stock no pueden ser negativos.

Las migraciones ejecutan un preflight antes de añadir restricciones: si hay datos inválidos abortan, sin remediarlos ni registrar la migración. Revisar y corregir explícitamente los registros antes de reintentar. `numeric(18,2)` y `decimal(18,2)` pueden redondear SQL directo antes de evaluar CHECK; solo API/Domain rechazan una fracción significativa superior a dos decimales, por lo que otros escritores deben validar antes de insertar.

Evidencia: `pwsh -NoProfile -File scripts/tests/Test-VersionedMigrations.ps1` pasó en SQL Server 2022 y PostgreSQL 17: 7 pruebas de migraciones y 3 de despliegue por motor. Incluye caracteres suplementarios, `NaN`, rechazo de preflight, datos e historial preservados y reintento. `dotnet test CleanArchitectureTemplate.slnx -c Release --nologo` pasó 248 pruebas y omitió 8 pruebas de aceptación que requieren contenedores (ejecutadas mediante el script). Revisión de Codex completada. Los límites del modelo EF se derivan de las constantes de Domain; las migraciones conservan sus valores históricos.

SQLite es exclusivamente efímero para Development/Testing: usa comparación NUMERIC para precios guardados como texto y no reproduce las garantías de precisión ni longitud de los motores productivos. Las invariantes de la aplicación siguen vigentes. Aplicar EnforceProductIntegrity con la operación de despliegue `migrate`, siguiendo [la guía de despliegue](database/deployment-operations.md), antes de iniciar el código nuevo. El preflight no recupera precisión ni texto que escritores anteriores ya hubieran redondeado o truncado.
